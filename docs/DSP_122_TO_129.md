# DSP releases 0.122–0.129

Each release has a guide, a runnable example, and a verification record.
From the workspace root, run `cargo run -p soniclaw-dsp-suite -- SUBCOMMAND OUTPUT_DIRECTORY`.
Create the parent directory first, then choose a new output directory for each run.

To use these outside the example program, import the modules from
`soniclaw::dsp` or `soniclaw_dsp`. IR capture, note transcription, SOFA file
decoding, and mastering render work belong off the audio thread. The FM, reed,
circuit, spectral morph, and prepared binaural renderers can be integrated into
an audio callback using their documented prepare and ownership contracts.

The reference checks include [ngspice transient simulation](validation/v0_124_0/reference.json),
[measurements from a SOFA render](validation/v0_127_0/example.json), and
[FFmpeg loudness measurement](validation/v0_129_0/reference.json). They cover the
included fixtures. Real recording quality, listener-specific spatial
perception, Windows/macOS behavior, and integration with external DAWs require
separate validation.
