# Submix, sidechain and master workflow — 0.81.0

## User workflow

Reference Studio adds **Submixes, sidechains and master chain**. Load stopped mixing draft snapshots the current song and live parameter values. Name a bus and Add submix. Set each track's output to Main or a named bus. A bus can feed another bus or Main, giving drum/instrument/vocal submixes and parent groups. Bus controls include gain, stereo balance, mute and solo. These are real summing buses with insert chains; the existing mixer control groups remain independent shared gain/mute controls.

Select a bus, choose a stock effect and Add submix insert, or Add master insert. The chain rows can move/remove inserts. Master has gain, balance and mute. Apply prepared mixing graph checks the entire candidate, prepares processors/delay storage, then adopts it. A feedback cycle, invalid processor, unsupported detector latency or stale draft leaves the current song intact. Applying is a project-history edit; Undo/Redo restores the model. Reload a draft after changing the song elsewhere. Removing a bus routes its children to Main and removes obsolete bus/effect parameter lanes on commit. Signal-path changes stop/snapshot playback first.

Play to use the live bus/master parameter sliders in the existing engine controls, including stock effect automation parameters. The mixing panel displays peak-hold meters for the prepared buses and master; opening/refreshing the panel consumes the accumulated peaks. These meters do not measure LUFS, true peak or gain reduction. Save stores the current normalized parameter values. Loading another mixing draft materializes those saved values into its bus/master controls, preventing an older model field from silently overriding a live fader edit.

To create ducking, select the destination track globally, choose another track as sidechain source, and Add ducking compressor to selected track. The detector listens to that source **after its track inserts and before strip fader/mute/solo**. Muting the source in the mixer therefore does not disable ducking. The new stock.sidechain compressor exposes threshold, ratio, attack_ms, release_ms and makeup_db through the usual parameter controls. Its peak detector and stereo-linked gain reduction receive the current block, including when the source appears after the target in track order. Remove selected sidechain and its compressor removes both the link and processor. Both source and target chains must currently declare zero processing latency; remove/replace lookahead, spectral or other delayed processors there before applying. Unrelated tracks and submix/master inserts may have nonzero compensated latency.

Track solo/mute and existing pre/post-fader auxiliaries keep their usual behavior. Bus solo enables its descendant tracks and required ancestor buses; other track branches are gated through the same smoothed mixer path, including their sends. Existing return-effect tails can decay. Muting an ancestor bus still mutes its path. Bus balance is unity at center; track panning retains the existing equal-power law. Faders, balance and gates smooth over approximately 5 ms; a prepared initial solo/mute mask is applied before playback starts.

## APIs and example

`studio::mix_graph::{Model,Bus,Master,Destination,Sidechain,Draft,sidechain_descriptor,Meter}`. Document.mix_routing stores the model. Outputs are Main or Bus(id); every track has one main destination, default Main. Every bus also has one destination. Model.validate checks the bus forest, sidechain dependency DAG, processor identities and limits. Draft::new captures a project baseline and current fader values. Edit its public document through typed Rust APIs, then Draft::apply(project, factory) returns a prepared session only after a validated candidate is ready. Publish or retire that prepared session through the normal engine lifecycle. Custom applications should wrap edits in History. The GUI drops an unpublished prepared audio lease before clearing its main-thread native owners.

`PreparedSession::mix_meters()` and `Controller::mix_meters()` expose Arc<Meter> peak exchanges; Meter.take_peaks consumes two channel peaks. Bus/master parameter IDs are bus.ID.gain, .pan, .mute, .solo and master.gain/.pan/.mute. Stock sidechain descriptors use their processor ID as the prefix. Existing normalized values and automation lanes share the ordinary parameter namespace. Adding a processor with a colliding parameter identity rejects instead of aliasing another control.

`Mixer::process_routed` adds per-track post-strip buffers and an audible mask while preserving the original process API. Main, post buffers and sends share exactly the same sample-by-sample fader/pan/gate decisions. initialize_audible is a preparation-side helper for an initial bus-solo mask. Custom callers must provide one correctly sized post buffer per input, or an empty slice, and an audible mask of the input count or empty.

Run `cargo run -p soniclaw-daw-mixing -- /tmp/soniclaw-mixing-new`. It builds two nested buses with declared test delays, a delayed direct track and master insert. Both paths arrive at sample 36 with the expected sum. It checks an additional delayed auxiliary return, bus solo/mute, master peak exchange, zero callback allocations, first-sample ducking from a muted later-indexed source, latency/cycle/stale rejection, duplication of a sidechain target, fader materialization, undo/redo and portable routing. The test.delay processor exists only in this example's explicit factory; it does not represent an installed native product. report.json contains measured values, not a JUCE performance comparison.

## Signal timing and ownership

Track rendering still aligns each track's instrument/inserts to the common track latency. Sidechain sources publish their pre-alignment PCM into prepared ChannelBus exchanges; a dependency order renders source tracks before detector targets. Since both involved chains must have zero latency, detector and target samples use the same source clock without a hidden previous-block delay. This is a bounded stock detector path, not arbitrary native bus negotiation or a complete general-purpose sidechain graph.

The prepared bus graph orders child buses before parents. Each summing node delays every incoming edge to the longest incoming path, then runs its inserts and smoothed strip. The main summing node includes direct tracks, terminal buses and compensated auxiliary returns, followed by master inserts/controls. The reported session latency includes the longest full path. Edge buffers, delays, meter atomics and parameter handles are allocated during preparation. Processing uses fixed-capacity scratch/post buffers, stack views and atomic exchanges; it takes no graph locks and allocates no routing storage. Seek/discontinuity resets routing delays and effect state. A changed latency/topology requires stopping and preparing another engine in reference Studio.

All drafts, graph validation, resource checks, processor instantiation, buffer allocation, saving and retirement belong to control/owner threads. Native factory ownership rules are unchanged; accepting a descriptor in a model does not authorize loading a module. The reference allowlist still controls native loading. Stock sampler references in submix/master descriptors are included in media audit, and opaque/native descriptors conservatively retain possible dependencies. Real native product behavior requires separate target acceptance.

## Persistence and migration

Document schema stays 1 with optional mix_routing, omitted when empty; Project remains schema 3. Legacy empty routes preserve the previous audio path and identity derivation. Older strict readers may reject populated new routing data. Model fields and normalized control values are saved; meter history and routing drafts are transient. Replacing/removing buses or processors cleans orphaned parameter values and automation lanes. Track duplication copies its bus output and remaps copied sidechain-target processor IDs/parameters. Deleting a detector source requires disconnecting its links first; deleting only a detector target removes its links. Freeze rejects a source/target that participates in sidechains until disconnected, avoiding an orphaned detector binding. Ordinary tracks feeding buses can freeze before the strip/submix path as before. Grouped elastic members retain their own dissolve-before-independent-edit requirement.

## Bounds, errors and known limits

Up to eight stereo submix buses, sixteen inserts per bus/master, 32 stock sidechain links and the existing 32 tracks/four auxiliaries/4096 parameters. Main outputs form an acyclic single-parent forest; feedback, arbitrary multi-output bus sends and bus-to-detector links are not represented. Track auxiliary sends remain the existing four pre/post-fader routes; auxiliary returns currently sum to Main. Source and target track latency must be exactly zero for a stock detector. Processor delay is bounded to 262144 frames per full route and aggregate compensation storage follows the existing 16-million-float budget. Peak meters use positive float-bit atomics and report post-strip absolute peaks.

Invalid/missing routes, duplicate identities, bus/sidechain cycles, orphaned detector descriptors, unavailable resources/processors, nonfinite/out-of-range controls, unsupported sidechain latency, excessive delay/parameter budgets, changed drafts and history failures report errors without adopting a partial candidate. Callback processing failures clear output and increment existing telemetry. A maximum legal graph can still exceed a machine's real-time CPU capacity; these limits are bounds, not a hardware load guarantee.

This release does not claim native plug-in automation, native offline owner management, hardware cue outputs, arbitrary native sidechains or complete routed stem export; those belong to subsequent releases in the requested mixing series. The reference mixing draft does not contain a native bus plug-in browser yet. Exact executed example/test/static-analysis/documentation evidence accompanies the release. Virtual tests establish the tested audio math and allocation behavior; physical audio/MIDI, third-party products and macOS/Windows runtime acceptance remain pending.
