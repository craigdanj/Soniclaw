# Unified live sessions (0.44)

## Workflow and runnable example

`cargo run -p soniclaw-studio-demo -- NEW_DIRECTORY` builds a two-track session containing looped PCM, a MIDI synth, inserts, an auxiliary delay, a mixer and beat automation. It renders the same three-second playback with 64/127-frame callbacks, records through the existing worker-backed recorder, saves a parameter/project snapshot, replaces the running session and retires the old resources. Its report records partition error, callback allocations, mapped playhead, revision and recording length. No device is opened by default.

To hear it on a configured 48 kHz default device, run with `--features native -- NEW_DIRECTORY --device`. That explicit flag opens audio for five seconds. The existing native adapter negotiates the device's default sample rate; the prepared session refuses a mismatched rate. Select/configure a suitable device or construct the document/assets from your DeviceManager plan in a product. The physical path is implemented but not claimed tested in this environment.

## Public API and application integration

`soniclaw::studio` reexports the standalone `soniclaw-studio` crate. A schema-1 Document contains the shared sample rate/block limit, musical Timeline, tracks, instrument/insert Descriptors, MixerModel, auxiliary return chains, normalized parameter snapshots and automation. Tracks contain audio/MIDI clips, an explicit input gain and an opt-in live MIDI route. Strip IDs/order must match track IDs. By default physical input is not monitored; set input_gain deliberately.

Compile with `document.compile(&assets,&mut factory)` on a control/resource thread. Builtins resolves strictly bounded sine/saw instruments, gain, low-pass and delay descriptors. A custom Factory returns Built {processor,parameters}, allowing registered DSP or prepared hosted processors. Descriptor JSON is configuration, never automatically loaded executable code. The caller must explicitly resolve/trust native modules and retain any required native main-thread owner outside the callback for its processor's complete lifetime. Returned processors are prepared once during compilation; wrappers must honor their own lifecycle restrictions.

`live_pair(prepared,latency_budget,fade_frames)` returns Controller and SessionProcessor. Move the processor into an Engine or the existing native callback adapter; keep Controller on the UI/control thread. Queue `set_playing` and `seek`; a full 32-command queue returns an error. Use returned shared parameters and automation Gesture handles for UI edits. Commands apply at the next callback boundary, not arbitrary offsets; MIDI within a callback retains exact frame offsets. Live MIDI reaches only tracks with midi_input enabled. Clip-generated and live events are merged with note-offs/panic ordered first.

## Shared rendering and latency

One clock drives analytic tempo/meter/loop/punch positions. Processing spans end at source-loop/tempo boundaries; beat automation uses the same TempoMap. Clip playback, synths and inserts share transport. Playback can stop while monitored input/live instruments and effect tails continue. Seeks invalidate clip and alignment continuity and send panic on the next actual rendered frames; they do not call arbitrary native reset methods or reconstruct historical DSP phase.

Within each track, clip/input PCM is delayed to match instrument latency before summing; inserts process that sum. Track outputs align to the longest track. Sends feed auxiliary chains, and the main/return paths align to the longest return. The fixed live-graph budget then pads the result and crossfades prepared replacements. All delays are bounded/preallocated and invalidate lazily on discontinuities. FX delay/reverb tails may persist after a seek; rebuild a session if complete DSP-history replacement is required. There is no feedback routing or automatic native bus negotiation.

`replace(prepared)` queues an already compiled session with an identical rate/block layout and latency within the existing budget. Failed compilation/publication retains the old session. Call `collect_retired` regularly to destroy old processors/assets/workers off the callback. Replacements receive the existing source position and playback state; held clip notes are reconstructed through the clip player. Pending external hardware notes/DSP history are not transferred automatically. `status.applied_revision` tells when a queued revision has processed; during a crossfade old revisions cannot overwrite the new revision's playhead. Diagnostic fields are atomic observations, not a multi-field transactional snapshot.

## Recording and persistence

Attach an existing `record::RecordTap` to SessionProcessor before starting its device. Its matching Recorder stays on the control thread and opens/finalizes files on a worker. This release integrates the existing stereo PCM16 dry/processed recording contract; multitrack recording is a later feature in this series. Dropped-frame/error reporting and explicit stop/finalization remain required. No recording silently restarts after device recovery.

`Controller::snapshot` requires the requested revision to be applied, copies its Document and captures current base parameter values as normalized stable-ID entries. Stop concurrent writers when a product requires an atomic multi-parameter preset; this API reads individual atomics. Custom/native opaque state must be captured by the application factory/owner into descriptor state separately. Document JSON is <=16 MiB, validates strict fields, and stores asset IDs rather than embedding PCM. Reattach immutable Assets by ID after load. Existing project/session formats are unchanged; this is an explicit new application-level format. Unknown factories/targets fail compilation instead of loading arbitrary code or silently substituting sound.

## Ownership, bounds, failures and validation

Compilation, file/device creation, snapshots, publication and resource retirement allocate and run on control threads. The callback processes preallocated buffers and bounded event/command queues without allocation, locks or I/O. Native processor-specific main/audio thread contracts still apply. Stop the device before final processor/controller teardown. No guarantee of deadline performance on arbitrary hardware follows from allocation-free code; profile the actual track graph.

Limits: stereo DSP, 8–192 kHz, maximum block 1–1024, 1–32 tracks, 1024 clips total (also per-clip toolkit limits), 16 inserts per chain, <=4 aux sends, 4096 unique parameter targets, 1024 combined MIDI events per track/block including panic/seek recovery, and 262144 frames total reported latency. Delay storage is capped at 16 Mi f32 samples. Individual descriptor state is <=64 KiB. Input/output samples must be finite and magnitude <=1,000,000. Discrete mute/solo mixer parameters use a 0.5 threshold; gain/pan/send targets use the mixer's smoothing law. Graph replacement temporarily runs both graphs and costs extra CPU/memory.

An event-density/processor/output failure silences the affected render span, counts the failure and schedules fresh panic/continuity recovery. It cannot roll back DSP already processed earlier in that span. Retain a known-good prepared session if rebuilding fails. Unprepared/invalid buffers are silent. `reset` avoids invalidating native leases; it clears timeline/delay continuity and schedules note panic rather than calling arbitrary insert reset routines.

Tests cover real clip/insert/mixer output, loops, sample-accurate automation, partition equivalence and zero callback allocations; stopped live MIDI and invalid-input silence; atomic graph replacement and control-thread destruction; document/factory validation; and actual recorder finalization. The runnable example joins these in one path. Physical I/O, external plug-ins/DAWs and Windows/macOS runtime acceptance remain pending unless separately recorded.
