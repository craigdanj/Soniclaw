# Soniclaw instrument/application SDK — v0.7

The six additions connect reusable APIs to the native workbench. Launch with
`cargo run -p soniclaw-workbench`; presets 4/5 are Poly Motion/Sampler Studio.
Panels 3–8 are Graph, Sample map, MIDI, Voice, Diagnostics and Host.

```sh
cargo run -p soniclaw-sdk-tools -- --demo /new/demo-folder
cargo run -p soniclaw-sdk-tools -- --audit /new/audit.json
cargo build -p soniclaw-workbench -p soniclaw-host-fixture
cargo run -p soniclaw-sdk-tools -- --host target/debug/libsoniclaw_workbench.so /new/host-renders
cargo run -p soniclaw-sdk-tools -- --host-contract target/debug/libsoniclaw_host_fixture.so /new/contract.json
```

Use `.dll` on Windows/`.dylib` on macOS. The walkthrough/audit requires no audio
hardware. Workbench startup renders a worker preview; Play opens the default device.

## Per-voice modulation

`dsp::voice_mod` provides two independent ADSRs and two five-shape LFOs per voice,
with up to 32 routes from envelopes/LFOs, velocity, centered key, pressure and
timbre to pitch, cutoff, level and pan. Each note retriggers its own modulation;
release/sustain are note-local. `PolyModSynth` exposes named gain, cutoff, pressure
and timbre parameters, reusing the expressive synth's note IDs/MPE behavior.
`VoiceModState` is reusable separately. No MIDI-2/RPN negotiation is added.

Depth is -1…1: pitch ±24 semitones, cutoff ±5 octaves, level `clamp(1+sum,0,4)`
and pan ±1. Seeded sample-and-hold is independent per note. Config is structural;
validate and reprepare or publish a new graph after editing. New project nodes
save `voice_modulation` and support explicit `mpe_*` zone settings. This is
independent from the existing global modulation matrix. Old sources default to
empty routing. The oscillator/one-pole timbre filter remain the existing DSP;
voice stealing/retriggers can be audible and sums can exceed unity.

## Visual/live graphs

`ui::GraphEditor` edits positions, cables/send gains, external input gains and
output selection in a draft. Click OUT then IN to connect; drag nodes. Apply
validates topology/resources before publication. Layout saves with the project.
Connections carry whole interleaved node buffers, not arbitrary channel matrices.

`graph::live::graph_pair` fixes spec/latency budget. Control prepares replacements,
rejects excessive latency and queues them. Audio compensates faster graphs,
warms the replacement, linearly crossfades, and returns retired processors to
control-side `collect_retired()`. Two-slot request/retirement queues bound growth;
backpressure delays swaps. Keep both owners alive and stop before destruction.
`replace_with_notes` seeds up to 128 messages only into the new graph. Combined
seed/input overflow emits all-notes-off. There is no processor-history transfer.

Workbench routing/map/MIDI/voice Apply uses a 2048-frame budget and 512-frame fade;
new graphs warm for that budget. This adds 42.67 ms at 48 kHz, reported during
live playback. Offline previews show unpadded latency. Choose a lower validated
budget through the API for latency-sensitive applications. The workbench seeds
its audition chord/on-screen held keys; external controller history is not copied.
Two graphs run during warmup/fade, increasing CPU/memory. Preset/source/serial
add/reorder operations can still stop playback. Resource construction can pause
control; there is no general feedback graph or guaranteed inaudible replacement.

## Graphical sampler editing

Sample map edits key/velocity rectangles, root note, round-robin group, gain,
one-shot/loop behavior and waveform region/loop markers. Drag rectangles to move
ranges, markers to change boundaries, or create 2–16 equal slices from key 36.

Memory `Zone` and saved `SampleZone` implement `start_frame`, optional exclusive
`end_frame`, and `loop_crossfade`. Regions reuse PCM. Loop bounds must lie inside
the region; fade ≤half the loop and ≤65536 source frames. The ending fade blends
into the start; wrapping resumes after the overlap, shortening the effective
loop by its fade. This is not pitch-preserving stretch. One-shot regions cannot
loop. Defaults preserve old full-sample playback. Disk factories reject non-default
slice/crossfade fields. File/waveform loading currently runs on the control UI.

## MIDI performance/files

`midi::performance` supports Off/Up/Down/UpDown/Random arpeggiation, up to eight
chord intervals, a scale mask/root, step/gate/swing, seeded positive timing and
velocity jitter. It has 128 held inputs, a 2048-event scheduler and explicit output
capacity. Processing allocates no queues. Overflow, transport stop or discontinuity
panics and clears state; note-offs cannot precede humanized onset. The project
wrapper uses the engine's 1024-event boundary. It currently requires playing
transport, including non-arp transforms. Constant-tempo output is block-partition
independent; future steps follow tempo changes without clock phase locking.

`SequenceNote`, `quantize_sequence` and `sequence_events` validate beat notes,
apply grid/strength quantization and produce timed notes. `MidiClip` reads PPQN
SMF type 0/1 and writes type 1 with a tempo track. Notes/CC/bend/channel/poly pressure
and tempo maps are retained. Limits: 16 MiB input, 64 tracks, 131072 events/tempos.
SMPTE, type 2, SysEx, program changes and other meta data are unsupported/skipped;
it is not lossless file editing. MIDI-1 export loses note IDs; releases need key/channel.

## Diagnostics

`diagnostics::audit` creates fresh processors across configured rates/block maxima,
varies actual blocks, injects notes/tempo changes and tiny denormal-range input,
and records finite output, peak, latency and callback timing/reset. `audit_state`
checks stopped state round trips, stable parameter identities and malformed input.
`CallbackStats` uses atomics with one audio writer; UI sees snapshots. Timing
and over-budget counts are not driver xruns or hard-real-time certification.

The optional `soniclaw-diagnostics/allocations` feature adds development heap probes.
SDK tools enable it; normal applications need not. It measures prepared callback/
reset sections, excluding factories/resources/reports/retirement. A host Rust
allocator probe cannot instrument arbitrary dynamic plug-ins' allocators. The
independent host fixture separately checks ABI/thread/timing/echo behavior.
