# Transients and phase-linked elastic editing — 0.80.0

## Workflow

Use **Transient and phase-linked elastic editing** in reference Studio. Register original disk WAVs with the existing waveform import panel; decoded sample-browser assets are a separate in-memory workflow. Select a destination track, choose an original WAV, and Add source to selected track. Repeat for linked microphones. Files must have the same sample rate and number of frames, so their original sample clocks align. A group accepts one to sixteen mono/stereo files. New groups start at the song playback cursor with endpoints spanning the original duration. You can also use a single file.

Select the reference source and Detect reference onsets. Threshold controls the fast/slow energy rise, Floor dB excludes low-level material, and Gap ms suppresses nearby repeat detections. These are candidates, not a beat-recognition or source-separation promise. Set Grid beats and Replace interior anchors with snapped onsets; endpoints remain fixed. Duplicate/colliding grid destinations are skipped rather than making a backwards map. Inspect the source-frame/target-beat rows and adjust them before rendering. Increasing marker coordinates and supported segment ratios are enforced at preparation.

Choose Preserve pitch for shared WSOLA time stretching, or Repitch for shared sample-position resampling that changes pitch with speed. Enter a **new** cache-folder path and Render and apply whole group. This is a bounded worker job; Cancel removes only its newly owned output folder. A changed song/draft is not silently overwritten by a late result. Applying stops at an error if the project changed, playback/recording resumed, a source changed or a cache cannot verify. Successful application is one project-history edit; Undo restores all original region enables and bindings, and Redo reinstates the group.

When there is an enabled whole-file, unlooped disk region for the original on its destination track, the UI records it as a replacement and disables it on commit, avoiding duplicate playback. Cropped/looped originals require an explicit render or another destination track; the group editor does not guess their acquisition alignment. APIs may leave Member.replace empty to append new regions deliberately. Existing MIDI, inserts and track mix settings remain on the destination track.

Select a saved group and Load saved group draft to adjust/rebuild all its caches together. Use a different new output directory for each generation. Dissolve shared edits; keep audio removes group enforcement but leaves the rendered regions, original resources and individual warp recipes. Dissolve before editing or freezing individual members, deleting group tracks or retiming a member independently. The single-file waveform editor rejects overwriting a grouped cache. This release does not provide automatic follow-tempo recomputation after arbitrary song tempo changes; existing cache guards require an explicit rebuild.

## API and runnable example

`studio::elastic::{Detection,detect,Member,Group,Ready,dissolve}`. A Member identifies original source, target track/region, generated cache asset and optional original region to disable. A Group has a stable ID, reference-member index and one tempo_cache::Recipe shared by every member. Group.validate checks identities, resources, equal acquisition shapes, target tracks, freeze/region conditions and working-file bounds. Group.quantize accepts ordered source-frame candidates and an absolute beat grid. It edits a cloned recipe and returns the number of retained interior anchors.

Group.build(project, new_directory, cancel) prepares without changing the project. Ready.apply verifies the original project baseline, each source/cache hash, recipe and timeline, applies every member to a candidate, then adopts the whole result. Wrap it in History::edit for undo in custom applications. All generated resources participate in the existing portable Project save/open and consolidation paths.

Run `cargo run -p soniclaw-daw-elastic -- /tmp/soniclaw-elastic-new`. The example creates four proportional microphone signals, detects four onsets, snaps three interior anchors, renders them together, verifies transient neighborhoods at samples 12000/24000/36000, checks cancellation, stale-job rejection, original-region undo/redo, group portability and dissolve without data deletion. report.json records the maximum phase residual of the related signals. It opens no hardware.

## Algorithm, ownership and persistence

TimeStretcher now supports 1–64 interleaved channels. Existing settings and all-channel analysis remain the default. Its new set_reference_channel(Some(index)) must be called before input; it chooses the channel used for WSOLA energy/correlation searches. Every channel still uses exactly the same grain position and overlap weights. The group renderer packs all original channels into one temporary float WAV, analyzes the first channel of the selected reference member, renders once through the existing bounded tempo-cache engine, and splits the output into normal mono/stereo caches. It never runs independent content-adaptive stretchers per microphone. For a stereo reference with a silent left channel, choose another reference source for useful correlation decisions. The onset detector uses peak channel energy rather than a potentially cancelling stereo sum.

Resampling, segment edges and overlap coefficients are shared. This preserves linear relationships between input microphones; it does not repair phase differences already present in the recordings, guarantee transparent sound for every transient, or eliminate WSOLA artifacts. Existing pitch-shifter processors retain their mono/stereo limits; widening the pull-driven stretcher does not widen every DSP module. Segment-boundary fades and the existing 0.5–2 preserve-pitch stretch ratio remain. The reference-channel choice is fixed during a stream; changing it after pushing input rejects.

Decode/analysis, file interleave/split, hashing, cache generation, recipe edits, validation and disposal belong to control/worker threads. Playback reads ordinary prepared disk regions with the existing bounded paging workers; it does no time-stretch allocation or filesystem setup in the audio callback. The shared scheduler reserves worker memory. Cancellation is checked during packing/rendering/splitting. A successful cache folder is retained for history/saving; a rejected stale result may leave a valid unused render folder for inspection, without changing the song.

Project schema remains 3 with optional layout.elastic_groups, omitted when empty. Each group's recipe/member identities are saved alongside the existing per-asset warp bindings. Older strict readers may reject populated new layout fields. Empty legacy layouts and existing one/two-channel stretcher JSON retain their meaning. Group metadata enforces shared changes but is not an independently playing audio track. Original and generated cache resources remain portable and verified by source, timeline and content hashes.

## Bounds, errors and verification

At most sixteen saved groups, sixteen members/group, 256 recipe endpoints/anchors (254 detected onset candidates), and 32 total channels in the group UI. The underlying stretcher supports 64. Originals are mono/stereo WAV at 8–192 kHz; acquisition rate and frame count must match. Onset decoding follows media_tools' 128 MiB PCM bound. Detection ratio 1.1–20, floor -80 to -6 dB and gap 10–1000 ms; grid 1/64–4 beats. Linked working WAVs are capped at 2 GiB; normal project media/cache, 16 streamed-region, four-hour/RIFF and tempo-render segment limits still apply. Disabled original regions count toward the streamed-region limit. Working files are streamed rather than decoded as a full multichannel array.

Invalid/nonfinite files, rates, identities, shape mismatches, generated caches used as originals, frozen tracks, duplicate sources, missing original regions, impossible recipes, stretch limits, occupied output folders, cancellation, changed sources/timelines and inconsistent saved bindings reject. Candidate edits preserve the prior song on failure. Existing output folders are never cleared by build. Source changes are checked before adoption; rebuild onsets when replacing an original file.

The example and regression test verify four-channel proportional phase residual and quantized transient locations, atomic history, save/open and error paths. A DSP regression changes a loud non-reference channel while requiring bit-identical reference output and preserved inverted/scaled channels. Existing no-allocation/partition WSOLA tests still run. Headless desktop checks cover group creation and duplicate-source rejection. Exact executed formatting, full-workspace all-target/all-feature Clippy, selected tests and warnings-denied Rustdoc logs accompany the release. These checks do not certify arbitrary recordings, physical interface/MIDI acceptance or Windows/macOS runtime.
