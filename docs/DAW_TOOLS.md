# Stock tools and media workflow — 0.79.0

## Use the reference application

Open **Stock instruments, effects and media**. Select a track, choose one of four starting sounds (sine keys, saw bass, square lead, slow pad), and Replace instrument. The sample loader can replace an audio or instrument track's instrument too. Choose one of 32 named DSP effects and Add insert. Select its processor ID below to move it up/down or remove it. Structural actions stop/snapshot playback first and participate in project undo. Effect controls are the existing engine-parameter sliders during playback; saved normalized parameter values and automation use the descriptor's stable ID. Synth envelope/waveform and sampler mapping are prepared settings, not live modulation controls in this panel.

Enter a directory and Refresh/search. The browser lists supported audio, MIDI and portable preset folders in that one directory; Open selected directory and Parent navigate explicitly, and the name filter applies on refresh. Set the song playback cursor before importing: audio starts there, and MIDI retains its tick-relative musical spacing there. Import audio adds a decoded clip to the selected track; Load sampler installs the audio as a pitched 64-voice sample instrument with the chosen MIDI root key (default 60). Audition stops transport, uses the output-only device route, plays at half gain for at most 30 seconds, and leaves project content unchanged. Stop ends it early. A hardware-device error is reported normally. The next song playback reapplies the configured input setup.

Import MIDI accepts PPQN SMF type 0/1, merges its performance tracks into one selected instrument track, and retains notes, channel bend, CC, pressure and poly pressure supported by Studio's MIDI editor. It does not create tracks from the file. File-tempo import optionally replaces tempo over the imported span, restoring the project's tempo afterward. A MIDI file with no initial tempo uses the SMF default 120 BPM. File-tempo overlay requires a stepped project tempo map; convert ramps explicitly first. Without this option, ticks follow the existing song tempo. Unsupported performance message types fail explicitly instead of silently claiming a lossless SMF round trip. Meter/key meta data, programs, SysEx and original SMF track/channel naming are not imported as project settings.

To save a preset select a stock processor ID, enter a name and a **new** folder path, then Save selected processor preset. A stock preset contains one processor, its parameter values and, for a sampler, its owned sample PCM. Browse that folder's parent and Load preset to install with fresh processor/resource IDs. Instrument presets replace the current instrument; effect presets append. Preset save never overwrites an existing folder. The saved preset does not include the song, performance clips, automation, insert chain or native executable code.

## Public API and example

`studio::stock::{EFFECTS,INSTRUMENTS,instrument,effect,set_instrument,add_effect,edit_insert,install_sample,AssetsFactory}` connects existing DSP implementations to portable Studio descriptors. `stock.fx` state has effect name and optional physical `values` keyed by parameter suffix. For example `{"effect":"gain","values":{"gain":0.5}}`. The document's normalized parameter map takes precedence at prepare; live snapshots persist those values. `stock.synth` state accepts waveform and attack/decay/sustain/release in seconds. `stock.sampler` accepts asset, root, one_shot, optional loop `[start,end]` frames and loop_crossfade, attack_ms/release_ms and bend_range. Unknown state keys and invalid loops/settings reject. The sampler uses SincFast playback, sustain/bend/expression handling and the existing MultiSampler voice engine; it is a single-zone workflow, not a new multisample mapping UI.

Use `AssetsFactory { assets: &project.assets }` for offline rendering, freezing and custom hosts containing stock samplers. Builtins alone handles stock effects/synths but intentionally cannot resolve a sample without a project asset map. A native host factory should delegate non-native descriptors to AssetsFactory; the reference GUI and its worker freeze/export paths do so.

`studio::media_tools::{scan,decode,place_audio,import_midi,save_preset,load_preset,install_preset,Preview}` provides the same operations independently. Decode returns project-rate mono/stereo PCM using SincBest resampling. WAV decoding is Rust/hound; AIFF/FLAC use the optional dynamically installed libsndfile backend and return an error when unavailable. Preset folders use the ordinary portable Project carrier/manifest and can be inspected without loading native libraries. Media audit recognizes stock sampler references in current and frozen-original documents rather than discarding apparently unused sample assets.

Run `cargo run -p soniclaw-daw-tools -- /tmp/soniclaw-tools-new`. It creates its own WAV and MIDI, checks sample-rate conversion, MIDI controls/tempo, sampler audio, smoothed gain silence, all 32 effects' preparation/finite processing, preset namespace remapping and portability after deleting the original WAV, sample-aware consolidation, browsing and audition PCM. It emits report.json. It opens no hardware.

## Latency, ownership and persistence

The reference app previously reserved a 4096-frame Studio replacement budget even for zero-latency tracks. Playback now passes the prepared graph's actual latency to live_pair. New MIDI `prepare_low_latency` and audio `prepare_low_latency_with_inputs` do the same; existing explicit-budget APIs retain their prior contract. Lookahead/FFT/native reported latency still applies; this change does not remove hardware buffers or guarantee a measured round-trip time. Topology/latency changes require stopping and preparing a new engine. Actual processor delay is compensated by the existing Studio mixer path.

Browsing, decoding/resampling, parsing, saving and preset loading are worker/control operations. Bounded shared jobs reserve memory and reject imports if the song changes before adoption. Import commits validate a cloned candidate, preserve the previous project on failure and join project history. Prepared audio callbacks contain sample Arcs and preallocated processors; they do no filesystem work. Preview performs no allocations/decoding in process(). Structural stock actions reject frozen tracks until unfreeze; replacing/removing a processor removes its obsolete parameter values and automation lanes, while reorder preserves them.

Project schema stays 3; new stock descriptor kinds and their resource references use existing fields. Older readers can read metadata but need an appropriate factory to render these kinds. Presets are standalone one-track portable carrier projects; no change to existing user files or old release notes. Browser location, edit fields and audition state are transient UI state.

## Bounds, errors, validation and limits

Directory enumeration is explicit, nonrecursive, skips dot names/symlinks and rejects over 4096 directory entries; query up to 256 bytes. Decode accepts files up to 1 GiB, at most 128 MiB source and destination float PCM, mono/stereo and project rates 8–192 kHz. Total project decoded resource limits still apply. Presets resample each sample within the same 128 MiB limit; the project aggregate budget remains enforced. SMF files are at most 16 MiB, 65536 performance events and four hours of imported duration. Existing Studio limits (32 tracks, 16 inserts/track, 4096 parameters, 1024 clips, 256 MiB decoded PCM) remain. Large CPU-heavy spectral processors are available but the catalog is not a CPU/load-admission guarantee.

Invalid formats, unavailable codecs, malformed state, identity collisions, missing assets, nonfinite PCM, frozen tracks, unsupported tempo overlays, stale jobs, invalid presets and occupied destination directories produce errors. Original media is never deleted by import/consolidation/preset loading. Delete a failed newly created output folder only after inspecting it; saving again uses a new destination.

Validation includes the runnable portable stock workflow and its regression test, desktop headless integration checks, full-workspace all-target/all-feature Clippy, selected Rust tests and warnings-denied Rustdoc; exact executed logs and machine-readable evidence accompany the release. Preparing all effects and checking finite output is a smoke check, not an audio-quality benchmark. Physical audition/MIDI, third-party products, AIFF/FLAC installation, macOS and Windows runtime remain pending.
