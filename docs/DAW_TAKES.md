# Grouped audio and loop MIDI takes — 0.76.0

## Audio workflow

Record a loop with several armed microphones/stems. Load its complete gap-free take in the existing comp editor, choose pass sections and crossfade size, then use **Apply current audio comp to all take stems** in Take groups. Every non-master stem receives the same recipe in one project-history transaction. Separate comp tracks keep the original files and tracks available. Active comp groups mute their original source strips and preserve/restore source solo state; deactivate the group to hear the sources. Group changes preserve destination inserts. Dissolve phase lock keeps the current audible mix but allows individual comp recipes to diverge afterward. Undo/redo covers selection and group changes without deleting recordings.

Dry-input stems copy their source insert chains with new descriptor/parameter identities and source mixer gain/pan/sends/automation. Rendered stems remain post-insert and do not receive the original inserts again. Native opaque states remain descriptions instantiated by an explicit trusted factory; group operations load no plug-in. Input calibration from the recording schedule adjusts source positions once; selecting a pass without the needed calibration pre-roll/tail is refused. Choose a covered pass or retain more surrounding recording. New comp tracks count toward the existing 32-track limit. Master is retained as a recording, excluded from automatic microphone grouping.

## MIDI workflow

Enable an arrangement loop, select an instrument track and **Record MIDI in arrangement loop mode**. Recording starts at the loop's beginning. Stop saves one raw performance with monotonic acquisition timestamps, original project positions and loop boundaries. The last complete pass becomes the editable clip. Select another pass under Take groups and MIDI loop passes; this replaces only that take's region and is undoable. A held note crossing a boundary is chased into the selected pass, then closed at its recorded off or the pass boundary. Raw sustain/bend/pressure/controller events are retained. Expressive clip playback/editing follows in the next release; raw pass SMF export already preserves those messages.

After reopening, choose a raw MIDI take index from the portable project and Load saved raw MIDI take, then select a pass. The raw performance fingerprint prevents an unrelated region from being overwritten. The original project's sample rate, track identity, tempo and loop definition must still match; stale selections reject. Loop capture does not silently flatten partial last passes. At least one full pass is needed for automatic application; otherwise the raw prefix remains saved. MIDI take folders advance automatically when a prior take folder exists, and new recorded region IDs use control-side identity allocation across reopened sessions.

## Interrupted audio recovery

In Recover interrupted audio WAV enter a Soniclaw recording WAV and a fresh destination path. Recover whole recorded frames copies the physically present finite float frames into a finalized new WAV. It ignores unfinished RIFF/data lengths and discards trailing partial-frame bytes. Original bytes remain untouched. The resulting path is offered to the existing audio-editor import workflow; audition it and choose timeline placement explicitly. Recovery cannot reconstruct audio still in a process buffer/device queue at the crash. It does not invent take/loop/clock metadata or call a recovered prefix a completed original take.

```sh
cargo run -p soniclaw-daw-takes -- NEW_DIRECTORY
cargo test -p soniclaw-studio midi_pass --all-features
```

The example records two synthetic input channels through four audio passes, applies a shared comp, checks source solo restoration and dry insert preservation, switches among four MIDI passes, exports a selected SMF and reopens a portable save. It then recovers a WAV with unfinished lengths/trailing bytes, checks the original is unchanged, refuses overwrite and rejects NaN PCM. MIDI tests compare 64/127-frame callback partitions and count callback allocations, including held-note chase and undo.

## API, ownership and persistence

`studio::takes::{apply_group,set_active,ungroup}` manages a complete audio group. `Project::apply_comp` now validates the complete candidate and preserves existing comp inserts. Grouped recipes cannot diverge through individual comp edits until the binding is dissolved. `midi_recording::Settings::looping`, `Take::{passes,pass,apply_pass}` provide capture and projection; `pass(index)` returns a linear take for `note_clip` or `smf`. `Take::apply` selects the last complete pass for loop takes. `workspace::identity(prefix)` creates a bounded stable new control-side ID. All these operations allocate/validate on the control side; native state remains main-thread owned and audio stops before structural publication.

MIDI capture callback copies events and loop markers into separate fixed queues. Raw acquisition time continues monotonically while the musical transport wraps. Event offsets and cycle boundaries come from the callback clock. The recorder drains on control, including a bounded cycle-queue snapshot; interrupted checkpoints account for a just-arrived cycle before the callback publishes its endpoint. Unexpected seeks/discontinuities and overflow remain visible and prevent clean-pass acceptance. The audio writer remains the sole file owner. `record::salvage::{inspect,recover}` performs bounded chunked I/O on a worker and exclusively creates its output.

Project schema 3 layout gains optional audio take-group and MIDI pass-selection maps. MIDI take schema 3 adds loop cycles, optional source positions and loop-mode settings; versions 1/2 remain readable. Missing maps/cycles preserve legacy behavior and project identity derivation. Old strict readers can reject added fields. Raw MIDI folders, group recipes, track state and selections survive ordinary saves/recovery/consolidation. Saves can hard-link an already copied disk asset into its owned raw-take folder, avoiding a second resource copy when the same recording is also an editable region. Only files within that new generation are linked; external source originals are never linked into ownership. Where hard linking fails, bounded independent copy remains the fallback. Generations are still immutable by contract and repeated saves still produce full generations.

## Bounds, errors and validation

At most 32 comp groups, 4096 MIDI selection entries and 4096 captured loop cycles; original track, streaming, metadata and portable resource bounds remain. The cycle queue has 4096 entries. Extremely short/long repeated recordings that exhaust it are marked discontinuous. MIDI raw events retain their 65536 limit; held-note chase can also hit that bound and then rejects projection. Only complete equal-length, latency-covered audio/MIDI passes are selectable. A group activation conflicting with another active group on the same sources is rejected. Source mute/solo automation must be disabled while the group controls those states; gain/pan/send automation is copied. Custom processor parameters must follow descriptor namespaces for cloning. Group deletion reconciles source states; deleting a selected MIDI region removes its selection metadata.

Salvage supports only this recorder's simple 44-byte RIFF float32 header, 1–8 channels, 8–192 kHz and at most two GiB. It rejects arbitrary WAV layouts, malformed headers, no full frames, nonfinite/extreme samples, existing destinations and failed I/O, removing only its new failed output. It is not a general WAV repair utility or guaranteed power-loss recovery system. A source changing concurrently is unsupported; stop its writer first. Whole-frame recovery and source preservation were executed in the example. Physical hardware, broad third-party plug-ins and Windows/macOS runtime remain pending. This completes the implemented recording workflow series; it does not imply the remaining production/mixing milestones are complete.
