# Coupled physical instruments

Construct CoupledInstrument with schema-1 Settings, up to 12 StringConfig values and an existing modal soundboard recipe. Prepare at the output rate. Strike a string with a velocity in 0–1 to apply a finite hammer pulse whose level and duration change with velocity. Pluck a string with a supplied pick position and deterministic seed. The strings feed a shared modal body. A smoothed and bounded body signal drives a second bank of tuned strings. Those sympathetic responses mix with the direct strings and body. Keeping the response bank out of the soundboard input prevents a circulating feedback loop. Set coupling to zero for the independent-string reference.

Use one mutable owner. The callback processes preallocated waveguide and soundboard state. strike schedules one bounded pulse and pluck initializes one string. tick renders one sample. AudioProcessor repeats the mono result in mono or stereo. string_values exposes the latest per-string samples to the owner. No block buffering latency is reported. Tune strings, body mode gains and levels with short renders first. This is a musical model with bounded drive and output, and measured acoustic matching is outside this release. It provides enough primitives for a keyboard or plucked instrument host to supply note mapping and damping behavior.

Persist Settings and reprepare at the next rate. Earlier waveguide recipes and tick behavior remain compatible. Limits are 1–12 strings, coupling 0–0.04, body mix 0–1, 0.2–8 ms hammer setting, 8–192 kHz, and at most two output channels. Existing string and modal frequency bounds apply. Invalid prepare preserves the live instance, invalid triggers reject, and reset clears resonance and excitation. The example serializes an instrument, compares coupled and uncoupled renders, checks sympathetic energy on an unplayed string and decay of the tail, verifies reset silence and measures callback allocations.

Run `cargo run -p soniclaw-dsp-suite --locked --offline -- coupled-instrument NEW_DIRECTORY`. [Executed checks](validation/v0_114_0/REPORT.md).
