# DSP additions in Soniclaw 0.138–0.144

These seven releases add reusable DSP to the Rust framework. Each release has its own guide, runnable example and Linux verification report.

| Release | Feature guide | DSP suite example | Verification |
|---|---|---|---|
| [0.138.0](releases/v0.138.0.md) | [Half-band filter design and custom oversampling](DSP_HALF_BAND_DESIGN.md) | `half-band-design` | [Report](validation/v0_138_0/REPORT.md) |
| [0.139.0](releases/v0.139.0.md) | [Shared convolution update queue](DSP_CONVOLUTION_UPDATE_QUEUE.md) | `convolution-update-queue` | [Report](validation/v0_139_0/REPORT.md) |
| [0.140.0](releases/v0.140.0.md) | [Lookup-table transforms](DSP_LOOKUP_TRANSFORM.md) | `lookup-transform` | [Report](validation/v0_140_0/REPORT.md) |
| [0.141.0](releases/v0.141.0.md) | [Borrowed audio sub-blocks](DSP_BLOCK_VIEW.md) | `block-view` | [Report](validation/v0_141_0/REPORT.md) |
| [0.142.0](releases/v0.142.0.md) | [First-order TPT filters](DSP_FIRST_ORDER_TPT.md) | `first-order-tpt` | [Report](validation/v0_142_0/REPORT.md) |
| [0.143.0](releases/v0.143.0.md) | [Logarithmic ramps](DSP_LOGARITHMIC_RAMP.md) | `logarithmic-ramp` | [Report](validation/v0_143_0/REPORT.md) |
| [0.144.0](releases/v0.144.0.md) | [Selectable panning laws](DSP_STEREO_PANNER.md) | `stereo-panner` | [Report](validation/v0_144_0/REPORT.md) |

From a source checkout, pass the example name and a fresh output directory. For example, the last release can run any of the seven commands.

```sh
cargo run -p soniclaw-dsp-suite --locked -- stereo-panner /tmp/soniclaw-stereo-panner
```

The example writes audio fixtures and a JSON report. Each feature guide covers preparation, callbacks, invalid inputs, state and migration. Soniclaw's APIs use Rust ownership and existing processor types. Verify response, delay and gain normalization against your target before changing a production signal chain. The source reports record synthetic Linux tests and the scope of each execution.
