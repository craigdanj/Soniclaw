# DSP releases 0.115–0.121

Each release adds a prepared DSP capability to the Soniclaw framework. Example commands run from the workspace root and take a new output directory.

| Release | Feature guide | `soniclaw-dsp-suite` subcommand | Validation |
|---|---|---|---|
| [0.115.0](releases/v0.115.0.md) | [Processor composition and latency-aware mixing](DSP_COMPOSITION.md) | `composition` | [Checks](validation/v0_115_0/REPORT.md) |
| [0.116.0](releases/v0.116.0.md) | [Advanced FIR and IIR filter design](DSP_ADVANCED_DESIGN.md) | `advanced-design` | [Checks](validation/v0_116_0/REPORT.md) |
| [0.117.0](releases/v0.117.0.md) | [Unified oversampling](DSP_UNIFIED_OVERSAMPLING.md) | `unified-oversampling` | [Checks](validation/v0_117_0/REPORT.md) |
| [0.118.0](releases/v0.118.0.md) | [Real-input FFT and analysis windows](DSP_REAL_FFT.md) | `real-fft` | [Checks](validation/v0_118_0/REPORT.md) |
| [0.119.0](releases/v0.119.0.md) | [Fractional-delay interpolation](DSP_INTERPOLATION.md) | `interpolation` | [Checks](validation/v0_119_0/REPORT.md) |
| [0.120.0](releases/v0.120.0.md) | [Reusable DSP utilities](DSP_UTILITIES.md) | `dsp-utilities` | [Checks](validation/v0_120_0/REPORT.md) |
| [0.121.0](releases/v0.121.0.md) | [Double-precision processing](DSP_DOUBLE_PRECISION.md) | `double-precision` | [Checks](validation/v0_121_0/REPORT.md) |

```sh
cargo run -p soniclaw-dsp-suite -- composition output/parallel-compressor
cargo build -p soniclaw-parallel-compressor --release
```

The parallel-compressor example is an exportable CLAP with a Wet Mix parameter and fixed 5 ms lookahead. An independent Linux CLAP host loaded the v0.115.0 binary and measured both stereo impulses at 240 frames, matching the reported latency at 48 kHz.

The [cross-release measurements](validation/v0_121_0/series-reference.json) include alias amplitudes for the oversampling example. In the 9 kHz drive fixture, three alias bins were below −80 dBFS at 8× and 16× in each mode. This result describes one workload. Filter coefficients and filter-order estimates also have a [SciPy comparison](validation/v0_116_0/reference.json).

The double-precision API covers application-owned audio buffers, gain, FIR/IIR and linked dynamics. Host, device, engine and Studio audio interfaces currently use f32. Linux x86-64 was used for the release checks. Windows, macOS, AArch64 runtime and external DAW acceptance need their own checks.
