# Soniclaw 0.6.0

Release date: 2026-11-16 (source developer release; no registry publication).

## Highlights

Six additions expand the framework from individual DSP units into configurable
instruments and processing racks, with a native workbench for trying them.

| Area | Delivered behavior |
|---|---|
| Modulation | Bounded routing, five LFO shapes with beat sync, curved multistage envelopes, eight macros and MIDI sources; saved base values stay separate |
| Multiband | Phase-aligned three-band compression, saturation, gain, mute/solo; signal-dependent dynamic EQ |
| Granular | Fixed grain/voice pools, seeded clouds, scanning/jitter/pitch/spread, sustain and note expression |
| Spectral | Freeze, robotisation, Hilbert frequency shift, real-time phase-vocoder pitch shift and offline stretch/pitch helpers |
| Convolution | Mono/diagonal stereo IRs, zero/uniform latency modes, direct/early/late kernels and bounded hot IR crossfades with control-thread retirement |
| Workbench | Native rack/controls/modulation UI, four presets, analysis/response displays, CPU/latency, undo/redo, resource import and portable project/WAV export |

## Added, changed and fixed

- Six new `AutomatedEffect` kinds (32 total), granular/convolution project nodes,
  named controls, optional modulation configuration and external WAV resources.
- Two separate Workbench CLAP exports: Multiband FX and Granular instrument,
  using the shared complete-state project factory and generic embedded editor.
- Hardware-free walkthrough renders all four presets, an IR crossfade and offline
  pitch/time examples, with self-contained project JSON/WAV resources.
- Prepared processing tests cover allocation and destruction, grain-pool pressure,
  release/sustain, phase-vocoder frequency behavior, stereo direct-reference
  convolution, latency, base-state identity and transactional route rejection.
- Larger control caches compare only active controls. Settled controls dispatch
  one whole block to the inner DSP, while changing controls retain per-frame
  smoothing. This addresses regressions observed during implementation; identical
  optimized 0.5/0.6 fixtures and raw measurements accompany the source.
- State reconstruction clears transient parameter offsets after a successful
  stopped rebuild; invalid reconstruction preserves current values.
- Pending preview requests coalesce behind a bounded single workbench worker.
  Existing module/format examples and all three project generators still check.

## Compatibility and migration

See [migration](../MIGRATION_060.md). `RackNode.asset` and
`ProjectState.modulation` require updates to Rust struct literals; new enum
variants affect exhaustive matches. Existing JSON reads without these optional
fields. Schema remains 2; strict older SDKs cannot read the new nodes/config.
Existing distributed product/parameter IDs are unchanged. New Workbench IDs use
`org.soniclaw.workbench.fx` and `.granular`.

Rust 1.100 remains required. DSP now uses serde for modulation config and rtrb
for bounded engine transfer. State depends on DSP's shared config; optional
workbench PNG capture uses image. Portable/core features remain separate from
native audio/UI; Workbench enables GUI by default and offers headless rendering.

## Known limitations

- Modulation is global; per-voice modulation and arbitrary live graph swapping
  are not included. Structural edits stop/rebuild. Dense modulation incurs
  per-sample graph dispatch and needs profiling for the target use case.
- Spectral transforms are basic phase-vocoder algorithms without formant,
  transient or stereo phase locking. Time stretching is allocating/offline.
- Convolution is diagonal stereo, not a four-channel true-stereo matrix. New IRs
  start cold and old tails end with the fade; fixed mode/rate/latency during swaps.
  Return retired kernels to the control thread and keep both queue owners alive.
- Granular PCM is memory-resident; fixed voice/grain limits can cause stealing or
  dropped grains. Rack saturation is not oversampled.
- Workbench resource loading/save can pause the GUI. It has a serial rack editor,
  text path inputs and default-device/test-tone playback, without a timeline,
  microphone input, third-party plug-in hosting or graphical sample-map editor.
  The standalone workbench is distinct from the generic embedded CLAP editor.
- Shared-VM microbenchmarks are not hard-real-time/DAW performance guarantees or
  a new comparison with JUCE. Windows/macOS runtime, physical devices, real DAW
  reopen/automation, fresh VST3/AUv2 wrapper validation and signing remain pending.

## Getting started

Run `cargo run -p soniclaw-workbench`, or use
`cargo run -p soniclaw-workbench --no-default-features -- --render /new/folder`.
Read the [workbench guide](../WORKBENCH.md) and
[module API/bounds guide](../DSP_MODULATION.md). Rendered projects/audio and
native screenshots accompany the example and validation folders.
