# Soniclaw 0.88.0 — Studio plug-in crash isolation

Release date: 2026-11-20.

## Highlights

Studio can run each supported stereo VST3 instance in an explicitly approved helper process. A crashed or timed-out plug-in falls back to silent output or delayed dry audio while the rest of the graph remains usable. Stop preserves its last good state and host control values; the user can quarantine, bypass or explicitly recover the instance with a fresh helper.

## Added and fixed

- Reusable `studio::isolation_adapter::{Policy, TrustedHelpers}`, independent executable approval, persisted recovery attempts and control-thread PID/fault diagnostics.
- Studio policy, session approval, fallback and recovery controls with history support. Reapproving a helper leaves the persisted attempt count unchanged.
- Continuous isolated native offline processing. Failed native exports are rejected and their newly created output directory is removed.
- Full musical transport forwarding through the matching helper protocol: PPQ, meter, bar, cycle, playing and recording flags. Typed note/expression transport remains supported.
- Verified last-good opaque or parameter-only state, including fallback if a helper fails during snapshot. Unsupported ordinary state calls still require an explicit parameter-only mode.
- The isolated live packet constructor is separated from the offline path so offline rendering fits the scheduler's normal worker stack in debug builds.
- A native owned-fixture example exercises child crashes, deadlines, dry/silent fallback, state recovery, fresh PIDs, allocation checks, Studio graph audio, helper denial and failed-export cleanup.

## Compatibility and migration

Workspace/internal packages advance to 0.88.0. Add `helpers: &Default::default()` to existing `NativeFactory` literals to deny child execution, or supply a separately approved `TrustedHelpers` capability. Exhaustive matches over the public native `Backend` enum must handle `IsolatedVst3` when the `isolation` feature is enabled. Enable host `studio,isolation` features; the facade's existing `plugin-isolation` feature can be combined with `studio-hosting`.

Rebuild the helper and parent together: this release adds a private protocol command for full musical context. Keep native product and parameter IDs stable. Saved descriptor isolation fields are optional, so old sessions require no schema migration. Helpers must be reapproved per application session; saved paths do not authorize executable launch. Recovery cannot restore unsaved internal edits or DSP histories.

## Known limitations

The Studio adapter currently supports stereo VST3, with host parameter controls. Isolated native editor windows, Studio multi-bus isolation and a Studio CLAP isolation adapter remain pending; the framework's existing lower-level CLAP isolation API remains available. Process isolation is a crash boundary, not a security sandbox. Live processing adds the existing 1024-frame bridge delay plus native latency. Physical audio/MIDI, third-party DAW/product acceptance and Windows/macOS runtime tests remain pending.

## Getting started

Read [Studio native isolation](../STUDIO_NATIVE_ISOLATION.md). Build `soniclaw-isolation-helper` and run `soniclaw-studio-isolation` with the owned protocol fixture and explicit helper path. The guide covers API migration, UI workflow, lifecycle, budgets, persistence, errors and runnable commands.
