# Soniclaw 0.92.0 — Compiled modulation and efficient control updates

Release date: 2026-11-20.

## Added

The reusable DSP module `modulation::compiled` resolves stable source/destination IDs and routes before rendering, then produces normalized modulation buffers without callback string searches or global parameter-atomic writes. Applications can bind these buffers to effects, instruments or voice-local processors independently of Studio.

- Audio-rate or stream-anchored control-rate source/route evaluation, with per-sample destination smoothing and base values kept separate from modulation.
- Constant and tempo/free-rate LFO sources, external scalar/audio bindings for envelopes, CCs and custom voice inputs, three route transforms and checked live source/base updates.
- Prepared output/resource budgets, f64 smoothing accumulation, deterministic reset, persistent schema-1 configuration and explicit evaluation counters.
- A standalone filter-modulation example with WAVs, external-envelope/config roundtrip checks, callback allocation counts and explicitly qualified timing observations.
- A nonlinear SVF refinement makes very small positive input drive approach its drive-zero linear path continuously; the feedback equation and bounds remain unchanged.

## Compatibility

Workspace packages advance to 0.92.0. Existing global and per-voice modulation APIs remain available with their existing preset formats; this is an additional compiled path. New configuration uses its own schema and does not serialize histories. Core/native product and parameter identities are unchanged. Native plug-in/Studio controls are not automatically connected to the new buffers; applications provide those bindings. The new SVF input-drive normalization is an intentional behavioral refinement at small drive values.

The first reusable DSP batch now spans [0.89.0 oversampling](v0.89.0.md), [0.90.0 nonlinear processing](v0.90.0.md), [0.91.0 filters](v0.91.0.md), and this modulation release. Remaining DSP areas and deferred Studio work are listed in the [roadmap](../DSP_ROADMAP.md).

## Validation

See the [executed full-workspace verification](../validation/v0_92_0/REPORT.md) and [standalone modulation report](../validation/v0_92_0/modulation.json). Checks include callback partition equivalence, phase/base preservation, malformed-input transactions, prepared memory limits, high-rate slow smoothing, filter drive continuity and zero allocation fixtures. Evaluation-count reductions do not imply an equivalent wall-clock CPU speedup. Timing observations are not worst-case real-time guarantees.

## Limits and usage

Read [Compiled modulation](../DSP_MODULATION.md) for lifecycle, threading, exact limits, API, persistence, failure handling and example commands. Audio mode is required for sample-accurate observation of external buffers; control mode quantizes updates. The sources are modulation generators rather than band-limited replacements for a synthesis oscillator. Hardware, external DAW, broad subjective sound quality and Windows/macOS runtime acceptance remain pending.
