# Soniclaw 0.4.0

Release date: 2026-11-16.

## Highlights

This developer release adds the five requested foundations: complete project
state and undo/redo, consistent live-effect automation, band-limited resampling,
seekable/per-voice disk playback, and expressive instruments.

## Added and changed

- Schema-2 `ProjectState`: product/name, current controls, relative sample assets,
  root notes, key/velocity zones, round robin, loop settings, rack configuration,
  connections and outputs. Schema-1 parameter documents can migrate to the new
  model; missing structure is not guessed.
- Bounded, labeled `ProjectHistory` snapshots and `ProjectSession` edits/undo/redo
  with reconstruction before commit. Safe relative asset resolution, cycle and
  bounds checks, bounded PCM import, and stopped-time engine reconstruction.
- Opt-in complete project state in `PluginInstance` and CLAP. Structural changes
  require deactivation and stable parameter identities; scalar snapshots stage
  at render boundaries. Legacy parameter-only products remain supported.
- `AutomatedEffect` with ten effect kinds, owned parameter metadata, stable named
  IDs and 10 ms per-frame control ramps. Dynamic filter/dynamics/modulation/wet
  controls update prepared storage without resetting tails. Variable-time delay
  joins gain, low-pass, peaking EQ, compressor, gate, chorus, reverb, limiter and
  oversampled drive in this control API.
- Linear, sinc-fast and sinc-best interpolation, bounded offline interleaved
  conversion, `AudioFile::resampled`, and quality selection in multisamplers.
  Spectral tests verify a passband tone and high-frequency alias suppression.
- `SeekablePlayer`: pause/resume, position, seeking, loops and EOF behavior.
  `DiskSampler`: independent voice/page caches, sample heads, background WAV page
  decoding, key/velocity mapping, round robin, pitch, sustain, attack/release,
  explicit PCM budgets and telemetry. Generation tags discard old seek/voice
  responses. Missing data silences that voice frame and advances time.
- `ExpressiveSynth`, explicit MIDI-1 MPE zones, master/member pitch combination,
  pressure, CC74 timbre and per-note tuning/pressure/timbre/pan/volume. Native CLAP
  note IDs/selectors and sample offsets route to expressive instruments. MIDI
  parsing now emits channel/poly pressure.
- A new `org.soniclaw.project-rack` CLAP example with six fully controlled effects,
  and a hardware-free `soniclaw-ecosystem` walkthrough with rendered audio/JSON.
  Extended exported-library smoke tests cover structural and scalar state.

## Compatibility and migration

- Existing reference product/parameter IDs and schema-1 state remain stable.
  The Project Rack has its own new identity and uses schema 2.
- `ParameterInfo` now has a borrowed lifetime (`ParameterInfo<'_>` in explicit
  type signatures); `Parameter` copies metadata into owned storage on creation.
  Ordinary struct literals keep working, and rack-generated IDs need no leaks.
- `MidiMessage` has new variants. Update exhaustive matches or explicitly handle
  unsupported expression events. Legacy `PolySynth`/`Sampler` remain available
  for basic notes; use expressive processors for isolated note IDs/MPE.
- The original exported demo synth now uses `ExpressiveSynth`. Its stable product
  and gain IDs are retained, but the default timbre/filter can sound different.
- Old `stream::open_wav` keeps its original forward-only behavior. Adopt the new
  APIs explicitly for seeking or disk-backed instruments.
- Sampler source-frame increments are bounded to 1/32–32; use appropriately rooted
  key zones for wider ranges.
- Preloaded `MultiSampler` keeps linear quality by default. New project sampler
  nodes/disk instruments default to sinc-fast; select quality while stopped.
- `read_wav` now applies a 256 MiB decoded-PCM limit. Use `read_wav_with_limit`
  with an intentional budget when a different allocation limit is needed.
- Stop processing before asset, graph, topology, sample-map or quality changes.
  Capture state before replacing the old instance. Revalidate native wrappers
  when upgrading a distributed product.

## Validation

Current Linux source, ABI, spectral, state and allocation evidence is recorded
in [the v0.4.0 report](../validation/v040/REPORT.md). Older CLAP/VST3 validator,
editor and performance results remain historical and were not reused as fresh
v0.4 measurements. The [validation index](../VALIDATION.md) distinguishes them.

## Known limitations

- Desktop GUI/DAW/hardware acceptance on Windows/macOS, AUv2, signing/installers
  and native v0.4 VST3 wrapper validation remain pending.
- Project documents reference external WAV assets. They do not embed PCM, persist
  playing voices/delay tails, serialize arbitrary user processor types, or provide
  a graphical DAW timeline/sample-map editor. Active graph swapping is unsupported.
- Disk streaming supports mono/stereo PCM/float WAVs. No compressed-bank codecs,
  time stretching, automatic I/O failure recovery or disk-stall-free guarantee.
  PCM budgets exclude decoder metadata/thread stacks. Offline renders can outrun
  read-ahead. Disk voice replacement fades in the new voice without a retiring
  crossfade; preloaded multisampling retains its separate crossfade behavior.
- MPE zones require explicit configuration. RPN auto-negotiation, MIDI 2, CLAP
  vibrato/expression-controller events, per-note parameter modulation matrices and
  emitted NOTE_END tracking are not implemented. Some expression transitions and
  hard voice steals/chokes can click.
- Sinc and live-coefficient paths have bounded work but no new performance-parity
  claim. The limiter is sample-peak, and effect settings are not acoustic-quality
  certification. Extreme transposition and dense automation need product testing.

## Getting started

```sh
cargo run -p soniclaw-ecosystem -- /new/output/directory
cargo build -p soniclaw-project-plugin
# Linux dynamic-export check; use the target platform's DLL/dylib path elsewhere
cargo run -p soniclaw-clap-smoke -- target/debug/libsoniclaw_project_plugin.so --project
```

The output directory must not already exist. The walkthrough writes an automated
rack WAV, a 44.1 kHz conversion, an expressive synth WAV, a seek preview and a
project JSON. See the [README](../../README.md) for native prerequisites.
