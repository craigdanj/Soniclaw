# Soniclaw 0.8.0 — 2026-11-17

This minor release adds portable project files, recoverable editing and background resource loading. It follows the completed six-area 0.7 SDK release.

Verified locally with 131 passing workspace tests, 36 prepared DSP audits, independent CLAP lifecycle checks and the project recovery walkthrough. Native panels were checked on a virtual display.

## Added

- Single-file `.soniclaw` bundles with scoped WAV assets, bounded lengths, SHA-256 corruption checks and no-replace output.
- Immutable checksummed recovery snapshots, bounded retention, corrupt/incompatible fallback and a bounded autosave worker.
- Latest-request-wins background project/resource loading, explicit queue backpressure/cancellation and optional worker preparation.
- Workbench pack/import, async JSON/recovery load, manual checkpoints, opt-in 30-second autosave and a scrollable project panel.
- SDK pack/unpack commands and an end-to-end portable sampler/recovery render walkthrough.

Project JSON schema remains 2 and exported product/parameter IDs are unchanged. Crates and format/package version metadata advance to 0.8.0. No published crates or binary-platform certification is implied.

Read the [workflow guide](../PROJECT_WORKFLOWS.md) for APIs, bounds and crash/asset limitations; [fresh validation](../validation/v080/REPORT.md) records the actual checks. Historical 0.7 notes and evidence are preserved.

Recovery depends on external assets. Bundles detect corruption but do not authenticate content. A crash during extraction can leave an incomplete new directory. Main-thread-only CLAP owners are outside the loader. Physical devices, real DAWs and Windows/macOS runtime acceptance remain pending.
