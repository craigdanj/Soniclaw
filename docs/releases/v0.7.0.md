# Soniclaw 0.7.0

Release date: 2026-11-17 (source developer release; no registry publication).

## Highlights

All six SDK additions are implemented: per-voice ADSR/LFO/source routing; visual
and prepared live graph routing; graphical sampler regions/slices/loop fades;
MIDI arpeggiation/chords/scales/swing/humanization/sequences/PPQN files; trusted
scoped CLAP hosting; developer stress/heap/state/CPU diagnostics.

Workbench now has six presets and nine panels. Its four CLAP products preserve
FX/Granular and append Poly Motion/Sampler Studio with new product IDs. Reusable
editor widgets, APIs and command-line walkthroughs exercise the same processors.

## Changes and compatibility

Graph replacements warm, compensate a fixed latency budget, crossfade and retire
resources off callback; optional notes seed only the new graph. Memory sampler
regions/fades affect actual playback. Native hosting joins audio before main-thread
state/destruction and negotiates native/MIDI dialects with bounded events.

Fixed zero-velocity identified-note release and rejected runnable projects with
no output. Added behavior, block-partition, allocation, queue/retirement and
independent exported-ABI host-contract checks. The workspace was recovered from
the saved 0.6 archive after a transient workspace reset; release evidence below
was rerun against the recovered source.

See [migration](../MIGRATION_070.md). New optional fields remain schema 2 and
retain old JSON defaults; Rust literals/exhaustive matches need updates. Runtime
memory zones add region/fade fields. Existing IDs remain unchanged; new products
are `org.soniclaw.workbench.polymod` and `.sampler`. Rust 1.100 remains required.
State/UI share MIDI/document types; optional hosting and heap-probe dependencies
remain separate from the portable/native feature boundaries.

## Validation

[Fresh verification](../validation/v070/REPORT.md) records actual commands/logs,
Rust tests, 36 audit configurations, state/heap checks, templates, CLAP exports,
four fresh-instance hosted renders, an independent MIDI-only/thread/timing/echo
fixture, native virtual-display captures, MIDI/sampler/voice/live-graph examples
and CPU fixture scope. Historical release notes and evidence remain unchanged.

## Known limitations

Hosting requires trusted conforming native code: no crash sandbox, hosted editor,
persistent device adapter, sidechain/f64/VST3/AU hosting or broad commercial
plug-in acceptance. Scoped main waits for audio; service callbacks between scopes.

Live replacement uses fixed latency, extra CPU and fresh processor history; old
tails end with the fade. Workbench seeds audition/on-screen notes, not arbitrary
controller history. Some serial/source operations still stop. Resource loading
and hosted previews can pause control. Sampler fades shorten overlap loops; disk
regions/fades and transient slicing are absent. MIDI has bounded overflow/panic
behavior, needs playing transport and does not edit SMF losslessly.

Linux builds/ABI/virtual-display checks do not establish physical devices, real
DAW GUI/reopen/automation, macOS/Windows runtime, fresh VST3/AUv2 wrappers, signing,
installers or remote CI. CPU fixtures on a shared VM are not universal guarantees
or a new JUCE comparison.

## Getting started

`cargo run -p soniclaw-workbench` opens the native application.
`cargo run -p soniclaw-sdk-tools -- --demo /new/folder` renders the SDK walkthrough;
`--audit /new/file.json` runs rate/block/heap/state audits. Read the
[SDK guide](../SDK_070.md), [hosting](../HOSTING.md) and
[workbench](../WORKBENCH.md).
