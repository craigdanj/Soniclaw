# Soniclaw 0.9.0

Release date: 2026-11-17.

## Highlights

A reusable audio output manager and custom DSP registry help application developers configure playback and extend Soniclaw without changing its built-in processor enum for every new effect.

## Added, changed and fixed

- Saved output/backend/rate/channel/buffer preferences, deterministic negotiation, polling/reconnect policy, explicit fallback and a reusable egui settings panel.
- Workbench Audio tab and managed live playback with the existing negotiated-spec graph path.
- Compiled Rust DSP registration, stable scalar parameter factories, optional custom editors, versioned configuration/defaults/migration and clear missing-registration failures.
- Registry-aware project factories, stopped host restore and background loading with canonical migrated state.
- Separate example Tape Colour processor crate, registered menu items, a seventh standalone preset and an audio/state/bundle walkthrough.
- Bounded project parameter-count validation after graph construction.

## Compatibility and migration

Workspace and package/format metadata advance to 0.9.0. Project schema remains 2; old built-in-only projects serialize with no new custom field. Existing product and parameter IDs remain unchanged. Custom projects require their processor crates to be compiled/registered and cannot be opened by older readers. Rust RackNode literals must add `custom: None`; prefer RackNode::new or registry.node. Existing output/duplex APIs remain available. New optional device UI uses the existing egui version and is enabled by facade device-ui.

See [registry guide](../REGISTRY.md) and [device manager guide](../DEVICE_MANAGER.md) for lifecycle, dependency and migration contracts. No crates are published by this source release.

## Validation

The final all-feature workspace suite passed 151 tests; 48 DSP audit cases, CLAP contracts, registered-state/audio walkthroughs, templates and native panel captures also passed. Fresh Linux checks and their exact limits are recorded in [the report](../validation/v090/REPORT.md). Physical hardware and real DAW acceptance remain pending; mock reconnect tests do not establish native driver reliability.

## Known limitations

The manager currently owns output streams; duplex input/recording still uses the separate existing API. Reconnection rebuilds DSP history. Device identity uses names/duplicate occurrence, buffer sizes are requests, and preference writes are not power-loss transactions. Registry code is compiled/trusted, not a dynamic plugin sandbox. State migration does not automatically rename exported parameters. Registry editors are egui callbacks, not hosted CLAP GUIs. Windows/macOS/physical-device runtime acceptance is pending.

## Getting started

`cargo run -p soniclaw-workbench -- --tab 9` opens settings; `--preset 6` opens Tape Colour. `cargo run -p soniclaw-sdk-tools -- --registry-demo /new/folder` generates the registry walkthrough. Read the guides above and the [workbench guide](../WORKBENCH.md).
