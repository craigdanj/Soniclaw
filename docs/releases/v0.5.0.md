# Soniclaw 0.5.0

Release date: 2026-11-16.

## Highlights

This release implements all eight requested DSP areas, with reusable algorithms,
automatable effect wrappers, project nodes and a hardware-free DSP Lab walkthrough.
It extends DSP capability; the separate UI/hosting/device roadmap is not claimed
as delivered by this release.

## Added and changed

- TPT state-variable low/band/high/notch filtering and a four-pole analytical
  ladder with resonance and input drive.
- LR4 two-way and phase-aligned three-way crossover kernels, plus individual
  band processors for graph composition.
- Linked RMS compression, attack/sustain transient shaping and a 4x-estimate
  lookahead limiter with declared latency and a safety margin.
- Reusable prepared FFT, periodic windows, normalized streaming STFT/overlap-add,
  spectrum analysis and a latency-aligned spectral-gate example.
- Harmonic mipmapped wavetable banks, frame morphing, phase-difference PWM,
  hard sync, fixed-voice/unison synthesis, detune and expression routing.
- Eight-line Householder FDN reverb with early reflections, predelay, input
  diffusion, damping/frequency-dependent decay and delay modulation.
- Phaser, flanger, tremolo, autopan and tempo-synchronised multitap/ping-pong delay.
- Monophonic YIN pitch analysis, finite-oversampling true-peak estimates, 48 kHz
  mono/stereo gated loudness, correlation/RMS and mid/side/width utilities.
- Sixteen new common effect kinds (26 total), corresponding project nodes and
  a basic-bank Wavetable project source with shared host-visible parameters.
- DSP Lab FX and Wavetable Lab CLAP exports, rendered audio/stems, FFT/analysis
  outputs, complete-state examples and an independent dynamic ABI smoke mode.

## Compatibility and migration

Existing product/parameter IDs and prior schemas remain stable. New demo IDs are
`org.soniclaw.dsp-lab.effect` and `org.soniclaw.dsp-lab.wavetable`. Project schema
stays 2; v0.5 adds processor-kind variants. Old projects load through existing
paths, while older framework versions cannot reconstruct new node kinds.

Update exhaustive matches over `EffectKind` and `ProcessorKind`. The new DSP
processors generally support 8–192 kHz; this does not reduce the older core's
supported preparation range. `LoudnessMeter` accepts 48 kHz mono/stereo only.
Wavetable project nodes reconstruct the built-in bank; custom wavetable assets
require an application-specific factory.

Structural configuration and full state reconstruction remain stopped-time
operations. Defaults have fixed lookahead/FFT latency, which Graph/PluginInstance
report and compensate: 252 frames for the default limiter and 1024 for the
spectral gate at 48 kHz. The combined DSP Lab FX reports 1276 frames. Source
controls/effect scalars follow the existing smoothing contracts.

Read [the DSP expansion guide](../DSP_ADVANCED.md) for ranges, ownership,
latency, supported formats and integration examples.

## Validation

See [v0.5.0 verification](../validation/v050/REPORT.md) for executed Linux commands
and results. Tests cover response/recombination, FFT/STFT reconstruction, spectral
behavior, latency, detector calibration, decay/reset, state/parameter identity,
automation partition independence and prepared callback allocation behavior.

The independent host loads the new exported library and exercises both products'
parameters, audio/notes, latency and full state. Earlier native VST3/AU/editor
and performance reports remain historical; they are not fresh v0.5 evidence.

## Known limitations

- No independent EBU/ITU compliance-vector certification. Loudness is mono/stereo
  48 kHz, with caller-bounded history; the peak detector/limiter are finite
  estimates and do not guarantee a ceiling after every possible downstream chain.
- Static wavetables are mipmapped, but hard sync/rapid morph/PWM and mip changes
  can alias or click. The ladder uses input saturation and an analytical linear
  feedback solution, rather than a fully nonlinear circuit solver.
- Recombined crossovers have all-pass phase. Spectral gating can produce musical
  noise and does not implement time stretching or spectral pitch shifting.
- Shared-stereo late reverberation is not spatial room modelling. Delay tap times
  clamp to fixed storage. Parameter smoothing does not make all mode/structure
  changes click-free.
- Analysis has bounded storage/work but some operations need a worker or a slower
  cadence. Prepared allocation checks do not establish CPU headroom on all targets.
- Windows/macOS runtime/DAW/hardware acceptance, new native VST3/AUv2 wrapper tests,
  signing/installers and fresh performance comparisons remain pending.

## Getting started

```sh
cargo run -p soniclaw-dsp-lab -- /new/output/directory
cargo build -p soniclaw-dsp-lab
cargo run -p soniclaw-clap-smoke -- target/debug/libsoniclaw_dsp_lab.so --dsp
```

The output directory must not already exist. DLL/dylib filenames differ by target.
See the [README](../../README.md) for native development prerequisites and the
archive's rendered examples for hardware-free inspection.
